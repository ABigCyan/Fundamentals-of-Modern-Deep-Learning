# 整体介绍

## 回顾 Model-Free RL（MFRL）
![[20-1-fig-1.png|571]]
[图片出处]([https://spinningup.openai.com/en/latest/spinningup/rl_intro2.html](https://web.stanford.edu/class/psych209/Readings/SuttonBartoIPRLBook2ndEd.pdf))
### RL 的目标

构造最优策略，最大化期望累计回报：

$$\pi^* = \arg\max_\pi \mathbb{E}^\pi \left[ \sum_{t=0}^{\infty} \gamma^t r_t \right]$$

### MFRL 的做法

- 直接学习 $\pi(a|s)$（policy-based）
- 或通过 $Q(s, a)$ 间接导出 $\pi$（value-based）
- 环境视为**黑盒**，只通过**交互样本**学习

**代表算法**：DQN, DDPG, PPO, SAC, TRPO …

## MBRL 关注环境本身的运行逻辑

$$p(s_{t+1} \mid s_t, a_t), \quad r(s_t, a_t)$$

**显式学习一个环境模型** $\hat{p}_\theta$（必要时连带奖励模型 $\hat{r}_\theta$）：

$$\mathcal{L}(\theta) = \mathbb{E}_{(s, a, s', r) \sim \mathcal{D}} \left[ -\log \hat{p}_\theta(s' \mid s, a) \right]$$

- 通常以**监督学习**方式在**真实数据集**上训练
- 模型学好后，**可在脑中推演**模拟真实交互

## MBRL 模型形式

- **确定性网络**：

$$s_{t+1} = f_\theta(s_t, a_t)$$

- **概率模型**：

$$\hat{p}_\theta(s' \mid s, a) = \mathcal{N}(\mu_\theta, \Sigma_\theta)$$

- **Ensemble**：捕获**认知不确定性**（PETS）
- **Latent Model**：在**隐空间**中建模（Dreamer / MuZero）

## Model 用来做什么

> MBRL 的重点不在"**怎么学**"模型，而在"**怎么用**"模型。

1. **生成数据**（扩充数据）
   - 离线产生 $(s, a, s', r)$ 样本，灌给 MFRL 更新 $\pi / Q$
   - **代表**：Dyna, MBPO
2. **Decision-Time Planning** — 在线规划下一步动作
   - 从当前状态出发，在模型中**搜索 / 采样动作序列**
   - **代表**：MPC, MCTS
3. **解析梯度反传** — 通过可微模型直接优化策略
   - 在模型中展开 $H$ 步，梯度回传到 $\pi$
   - **代表**：Dreamer 系列

## 相比 MFRL 的优点

1. **样本效率高**
   - 通常比 MFRL 高 **1~2 个数量级**
   - 例：**PETS** 在 Half-Cheetah 上 $\sim 10^5$ 步 $\approx$ MFRL 的 $10^6$ 步
   - **交互代价高的场景**（机器人、医疗、金融）**天然优势**
2. **环境模型与奖励解耦，复用性强**
   - 换任务只需换 reward，$\hat{p}_\theta$ 可直接复用
   - 天然适配 **Multi-task**
3. **支持多步 planning & 约束**
   - 可加入**安全约束**：先在模型中模拟，再决定执行
   - 决策过程**可解释**，便于**调试与审计**

## 相比 MFRL 的缺点

1. **Compounding Error & Distributional Shift**
   - 模型误差随 horizon **复合增长**（最坏 $\mathcal{O}(H^2 \epsilon)$）
   - 训练与推理看到的数据分布不一致，导致 **OOD**
2. **难以建模复杂对抗博弈**
   - 对手策略难以监督学习
3. **渐进性能往往劣于 MFRL**
   - 真实数据充足时，MFRL **无模型误差上限**

> [!note]
> **Horizon = 决策时考虑的未来时间范围。**  
> **短 horizon：只看眼前；长 horizon：考虑长期收益。**
## 什么时候可以用 MBRL？

- **真实交互昂贵**
  - 机器人、医疗——每一步都有**成本 / 风险**
- **环境动态规律可建模，甚至有完美模型**
  - 棋类 / 简单游戏等：**规则明确** ⇒ 模型几乎**无误差**
  - **AlphaGo / MuZero 成功的根基**
- **奖励可能变化，需要迁移**
  - 调整决策风格（保守 ↔ 激进）
  - 只改 cost，**模型与 planner 直接复用**

> **反之**：动态极复杂 + 海量数据 + 无迁移需求 ⇒ **MFRL 通常更稳**

## Background Planning

**核心思想**

- 训练期间利用**环境模型**，**离线生成大量虚拟经验**
- 扩充后的数据喂给 **MFRL 式更新**，改进 $\pi / Q$
- 决策时：直接查策略，**不再使用模型**

**代表算法**：Dyna-Q, MBPO, Dreamer

## Decision-Time Planning

**核心思想**

- 每次决策时**基于模型向前推演若干步**
- 搜索 / 采样动作序列 $a_{t:t+H}$，按**累积 reward 排序**
- 只执行序列的**第一个动作** $a_t$，下一步**重新规划**

**代表算法**：MPC (Random Shooting / CEM), MCTS, MuZero

# MBRL 基础

## Dyna：Background Planning 的开山架构

Dyna 属于 Background Planning 范式。

Sutton（1990）提出的**统一框架**：把**直接 RL、模型学习、规划**三件事融合在**每一次迭代里**。

- 真实样本 → 更新 $Q$（**direct RL**）
- 真实样本 → 更新模型（**model learning**）
- 从模型采样 → 再更新 $Q$（**planning**）

以 **Dyna-Q** 为最经典实例。

### Q-Learning vs. Dyna-Q

| **Q-Learning**                                                                                                                                                                                                                                               | **Dyna-Q**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初始化 $Q(s, a)$<br>**loop**:<br>&nbsp;&nbsp;$s \leftarrow$ 当前状态<br>&nbsp;&nbsp;$a \leftarrow \varepsilon\text{-greedy}(Q, s)$<br>&nbsp;&nbsp;执行 $a$，观测 $r, s'$<br>&nbsp;&nbsp;$Q(s, a) \mathrel{+}= \alpha \big[r + \gamma \max_{a'} Q(s', a') - Q(s, a)\big]$ | 初始化 $Q(s, a)$，<font color="#ff0000">$\text{Model}(s, a)$</font><br>**loop**:<br>&nbsp;&nbsp;$s \leftarrow$ 当前状态<br>&nbsp;&nbsp;$a \leftarrow \varepsilon\text{-greedy}(Q, s)$<br>&nbsp;&nbsp;执行 $a$，观测 $r, s'$<br>&nbsp;&nbsp;$Q(s, a) \mathrel{+}= \alpha \big[r + \gamma \max Q(s', \cdot) - Q(s, a)\big]$<br><font color="#ff0000">&nbsp;&nbsp;$\text{Model}(s, a) \leftarrow (r, s')$<br>&nbsp;&nbsp;**for** $i = 1 \ldots n$:<br>&nbsp;&nbsp;&nbsp;&nbsp;随机取曾访问的 $(\tilde{s}, \tilde{a})$<br>&nbsp;&nbsp;&nbsp;&nbsp;$(\tilde{r}, \tilde{s}') \leftarrow \text{Model}(\tilde{s}, \tilde{a})$<br>&nbsp;&nbsp;&nbsp;&nbsp;$Q(\tilde{s}, \tilde{a}) \mathrel{+}= \alpha \big[\tilde{r} + \gamma \max Q(\tilde{s}', \cdot) - Q(\tilde{s}, \tilde{a})\big]$</font><br> |

### Dyna 的优缺点

#### 优点

- 每一真实步被**回放 $n$ 次** ⇒ 相较 Q-Learning **大幅提升样本效率**
- 规划时每次只 rollout **一步**，**compounding errors 小**

#### 局限

- 随机取历史 $(s, a)$ 回放 ⇒ **不适用于非平稳环境**
- MBRL 框架无法完全消除 **distribution shift** ⇒ 渐进性能通常**劣于**纯 Q-Learning

### Dyna-Q 简要小结

- **超参 $n$**：每个真实 step 后做多少次虚拟更新；$n = 0$ **退化为 Q-Learning**
- 迷宫类任务中，$n = 50$ 可比 $n = 0$ 收敛步数少**一个数量级**
- 现代 **MBPO、Dreamer** 本质上都是 Dyna 的**连续 / 深度变体**

## MPC：Model Predictive Control

MPC 属于 Decision-Time Planning 范式。

相比 Dyna，MPC 更像一种**基于模型的搜索算法**，而非完整的 MBRL 框架（PETS）。

假设已有训练好 / 完美的模型 $\hat{p}$，在 $s_t$ 求解：

$$a_{t:t+H-1}^\star = \arg\max_{a_{t:t+H-1}} \mathbb{E}_{\hat{p}} \left[ \sum_{k=0}^{H-1} \gamma^k r(s_{t+k}, a_{t+k}) \right]$$

- 只执行**第一个动作** $a_t^\star$
- 在 $s_{t+1}$ **重新求解**（receding horizon）
- 每步用**真实状态重置起点** ⇒ 对**模型误差鲁棒**
![[20-1-fig-2.png|557]]
### MPC 的常用求解方法

#### Random Shooting

- 从 $\mathcal{U}(a)$ 随机采样 $N$ 条动作序列 $a_{t:t+H-1}$
- 用模型 rollout 每条序列，计算累积奖励，取**最优序列的第一个动作**
- 实现简单；**动作维度高时效率低**

#### CEM（Cross-Entropy Method）

- 维护高斯分布 $\mathcal{N}(\mu, \sigma^2)$，迭代采样 $N$ 条
- 每轮保留 top-$k$ 精英样本，用其**均值 / 方差**更新 $\mu, \sigma$
- **PETS、TD-MPC 等广泛采用**

**其他方法**：iLQR / DDP（可微模型），MPPI（路径积分）…

### MPC 的优缺点

#### 优点

- 完全**不需要训练 policy**，只需一个够用的模型
- 改变奖励函数**不需要重新训练**——直接改 $r$ 即可
- 天然支持**硬约束**（安全、能耗、几何等）

#### 缺点

- **推理开销大**：每一步决策都要做一轮搜索
- 性能受 horizon $H$ 限制——**过长误差大，过短短视**

## MCTS：Monte Carlo Tree Search

MCTS 同样属于 **Decision-Time Planning**。

与 MPC 不同，MCTS 更擅长**离散动作空间**，是 **AlphaGo / MuZero** 的核心搜索算法。

**核心思想**：在当前状态 $s_t$ 建一棵搜索树。

- **节点 = 状态，边 = 动作**
- 反复执行**选择-扩展-模拟-回传** 
- 最终选**访问次数最多**的子节点作为动作

### MCTS 的四个阶段

循环 $N$ 次：

1. **Selection**：从根出发，用 **UCB** 递归选子节点直到叶子

$$a^\star = \arg\max_a Q(s, a) + c \cdot \sqrt{\frac{\ln N(s)}{N(s, a)}}$$

2. **Expansion**：在叶子节点**展开合法动作**子节点
3. **Simulation**：从新节点 rollout 到终局得到回报 $G$（或用值网络 $V(s)$ 直接估计）
4. **Backup**：沿路径**回传**更新 $N(s, a)$ 和 $Q(s, a)$

搜索结束后按**访问次数**输出动作。
![[20-1-fig-4.png|430]]

[Monte Carlo Tree Search: A Review of Recent Modifications and Applications](https://arxiv.org/pdf/2103.04931)

### MCTS 伪代码

```python
def MCTS(s_root, N_sim):
    for _ = 1..N_sim:
        path ← [s_root]
        # 1. Selection
        while not is_leaf(path[-1]):
            a ← PUCT_select(path[-1])
            path.append(step(path[-1], a))
        # 2. Expansion
        expand(path[-1])
        # 3. Simulation
        v ← V_network(path[-1])    或 random rollout
        # 4. Backup
        for s, a in reversed(path):
            N(s, a) += 1
            Q(s, a) += (v - Q(s, a)) / N(s, a)
    return action_from_visit_counts(s_root)
```

### MCTS vs. MPC

|  | **MCTS** | **MPC** |
|---|---|---|
| 动作空间 | 离散 | 连续 |
| 规划形式 | 树搜索 | 轨迹优化 |
| 随机性 / 博弈 | 原生支持 | 需期望化 |
| 典型应用 | 棋类、Atari | 机器人、控制 |

两者都是 Decision-Time Planning，但**结构化程度不同**：MCTS 在**离散树**上搜索，MPC 在**连续轨迹空间**优化。
